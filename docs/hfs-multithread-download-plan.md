# NtoNTier v1.2.0 方案：HFS 文件切片 + 多线程下载

> 版本日期：2026-09-04
> 前置：v1.1.1（连接方式标签版）已封版备份，本方案在其基础上规划 v1.2.0。

---

## 一、目标

在客户端内对 HFS 共享的文件支持「切片 + 多线程下载」：
- 大文件在虚拟局域网内**显著提速**（多 TCP 连接并行，绕过单流限制）
- 支持**断点续传**（中断后重试只补缺失段）
- 全程在软件内部完成，不需要外部下载工具

## 二、可行性结论（已实测 HFS 3.2.2）

切片下载的核心前提是 HTTP Range，**已用独立实例实测通过**：

| 测试 | 请求 | 结果 |
|---|---|---|
| 探测 | `HEAD /testfile.bin` | `Accept-Ranges: bytes` + `Content-Length: 5242880` |
| 切片 | `Range: bytes=0-99` | **206** + 100 字节 ✓ |
| 任意段 | `Range: bytes=1048576-1048675` | **206** + 100 字节 ✓ |
| 断点续传 | `Range: bytes=-500` | **206** + 500 字节 ✓ |

→ **无需改 HFS 服务端**，HFS 天然支持分段请求，客户端直接发起 Range 即可。

## 三、下载流程（核心机制）

```
用户输入文件 URL
   ↓
① HEAD 探测：拿文件总大小 + 确认 Accept-Ranges
   ↓
② 切片：按线程数 N 切成 N 段（每段 ≥ 256KB，小文件自动降级单线程）
   ↓
③ 并行下载：N 个 Task 同时请求各段（Range: bytes=s-e），流式写入各自 .part 文件
   ↓
④ 进度汇总：每段已下载 → 总进度 + 实时速度
   ↓
⑤ 合并：全部完成按偏移拼接 .part → 最终文件，删除分片
   ↓
（中断时）⑥ .part 保留，重试跳过已完成段 = 断点续传
```

## 四、技术实现（C# .NET 4.8，现有工程）

### 新建 `DownloadManager.cs`
- **DownloadTask**：URL / 总大小 / 线程数 / 本地保存路径 / 状态 / 进度回调
- **Segment**：start / end / 已下载 / 完成标记
- **Start()**：HEAD 探测 → 切段 → `Task[]` 并行调度
- **每段下载**：`HttpWebRequest` + `AddRange(start, end)` + 流式写 `.partN` 文件（不占内存）
- **Merge()**：按偏移 `BinaryWriter` 拼接各分片
- **事件**：`OnProgress(总百分比/速度)` / `OnCompleted` / `OnError`
- **并发限制**：`ServicePointManager.DefaultConnectionLimit` 提到线程数（默认 2 会卡并发）

## 六、性能与取舍

| 场景 | 多线程效果 | 说明 |
|---|---|---|
| 打洞直连（P2P） | ⚡ 显著提速 | 多连接并行，4~8 线程最佳 |
| 服务器中继 | 提速有限 | 服务器带宽是瓶颈，但断点续传仍有效 |
| 单线程（保底） | 兼容一切 | 小文件 / 未知服务器自动降级 |

- 分片大小 ≥ 256KB，避免小文件开多线程浪费
- 文件 < 1MB 自动单线程
- 流式写盘，峰值内存 ≈ 网络缓冲，不随文件大小增长

## 七、边界与风险

- **中文字符/空格文件名**：URL 需 `UrlEncode`；最终文件名从响应 `Content-Disposition` 提取
- **HFS 匿名只读**：默认可直接下载；若共享目录开了账号权限，需确认 HFS 匿名访问是否放行（v1.1.1 配置默认匿名可读，通常无此问题）
- **磁盘空间**：合并前需「最终文件 + 分片」≈ 2 倍文件大小，UI 提示
- **中继提示**：可联动 v1.1.1 连接标签，检测为「服务器中继」时提示"当前走中继，多线程加速有限"
- **并发连接**：`HttpWebRequest` 的 `ConnectionLimit` 必须设为线程数，否则并发被内核限到 2

## 八、实施步骤（v1.2.0）

1. 新建 `DownloadManager.cs`（核心逻辑，可独立跑命令行自测）
2. `MainForm.cs` 加「下载管理」页 + 导航 + 任务列表 UI
3. `Config.cs` 加下载配置项
4. 与连接标签联动：中继时提示加速有限
5. `build.bat` 入链
6. 编译 → 单机自测（本机起 HFS + 5MB/50MB 文件多线程下载，验证进度/合并/断点/MD5）
7. GUI 验收（复用 OrganizeAgent）：下载页 UI + 实际下载完整文件，**MD5 与源文件一致**

## 九、验收标准

- 50MB 文件 4 线程下载成功，合并后 MD5 = 源文件 MD5
- 下载中断 → 重新开始 → 从断点续传（已下载段不重下）
- 直连/中继两种连接状态下均能下载（中继允许更慢）
- 下载页 UI 与整体风格一致（极简扁平、暗色/亮色主题）
